# 前端融合优化记录

## 资料观察

- 图片统一采用深色控制台风格：固定左侧导航、顶部运行状态、卡片化内容区、青色信息色与橙红色风险色。
- 任务编排页强调“新建任务 → 任务列表 → 进入任务详情”，详情页使用会话、总览、探索链路、AI 思考、漏洞、测试资产、资产覆盖图、拦截审批和报告等工作区标签。
- 黑板模型以 `Origin → Intent → Worker → Fact → Goal` 表达探索状态；节点和边需要可追溯，而不是只展示自然语言对话。
- AI 思考页展示公开的阶段摘要、工具调用和验证结果，避免展示隐藏推理；运行日志需要支持筛选和错误突出显示。
- 工具矩阵、MCP、Skill、Agent 清单和平台配置属于能力管理入口，适合放入导航分组并保持与任务运行状态分离。
- PDF 的理想化 Loop Engineering 模型强调 Outer/Middle/Inner 三层循环、反馈可信度、假设验证、停止条件和独立验证。

## 本次落地决策

1. 保留现有 React + Ant Design 和实时 WebSocket 数据链路，避免重写稳定功能。
2. 在 Workbench 顶部增加运行概览和阶段标签，先让核心任务路径接近参考图。
3. 用事件数据派生黑板节点、资产覆盖和审批/日志面板；没有后端数据时显示明确的空状态。
4. 所有新增组件只消费现有 `run/report/events`，不改变后端接口契约。
5. 每个阶段完成后执行前端构建，确保算力受限时仍可回滚和验证。
